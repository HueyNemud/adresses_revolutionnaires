# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Pipeline turning scanned historical Paris directories (annuaires, early 1800s) into structured entries (ENTRY) nested under a title hierarchy (TITLE), then splitting each entry into NER spans `SUBJ` / `DESC` / `ADDR`, then aligning the entries of two editions. Code, comments, CLI help and docs are in **French**; command and option names are in **English**; keep new code consistent with that.

## Commands

Managed with `uv` (Python ≥ 3.12). The code is the installable package `src/numrev/` (hatchling); `uv sync` installs it with the single entry point `numrev`. Run everything from the repo root (data paths are relative). No pytest. Formatter: **black** (line length 140, `[tool.black]`); linter: **ruff** with flake8's default rules (pycodestyle `E`/`W` + pyflakes `F`) plus import sorting (`I`); both are in the default `dev` dependency group. flake8 itself is deliberately not used: ruff implements the same rules (checked: identical findings), so it would only duplicate the config. Run black then ruff before committing code.

```bash
uv sync                                                    # install deps + the `numrev` command into .venv
uv run numrev                                              # list of commands (pipeline steps 1–7, then tools)
uv run numrev <command> --help                             # options of one command
uv run python -m unittest discover -s tests                # all tests (unittest, not pytest)
uv run python -m unittest tests.test_tabulate              # one test module
uv run python -m unittest tests.test_tabulate.<Class>.<test_name>   # one test
uv run black src tests                                     # format (line length 140)
uv run ruff check src tests [--fix]                        # lint: flake8 rules (E, W, F) + import order

# Steps 1–5, per page range (D = annuaires/<volume>/<range>/<volume>.<range>)
uv run numrev extract  $D.ocr.json --apply                 # 1 → $D.lines.json
uv run numrev label    $D.lines.json --apply               # 2 → $D.labeled.json (+ $D.label-session.json)
uv run numrev tabulate $D.labeled.json --apply             # 3 → $D.lines.csv (hand-curated)
uv run numrev assemble $D.lines.csv --apply                # 4 → $D.entities.csv (+ .entities.report.txt)
uv run numrev tag $D.entities.csv --model models/<m>.gliner-model --apply   # 5 → $D.ner.csv (hand-curated)
# Steps 6–7, per pair of complete volumes
uv run numrev align nw annuaires/<A> annuaires/<B> --apply           # 6, order-based (Needleman-Wunsch + pair-HMM), no training
uv run numrev align dedupe annuaires/<A> annuaires/<B> [--label] --apply      # 6, Dedupe + entry patch
uv run numrev align dedupe annuaires/<A> annuaires/<B> --patch-only --apply   # reapply the entry patch, no Dedupe
uv run numrev align dedupe annuaires/<A> annuaires/<B> --raw-sections --apply # Dedupe variant with per-volume section keys (comparison)
uv run numrev join annuaires/alignments/<A>__<B>.nw.csv [--excel] --apply    # 7, readable joined CSV for data users
# Viewers, models, evaluation
uv run numrev view directory                               # Streamlit viewer of a volume's final NER CSV
uv run numrev view alignment                               # Streamlit alignment viewer: review decisions → entry patch; documents diff; CSV export
uv run numrev publish-viewer ../alignment-viewer --apply   # regenerate the hosted (Streamlit Cloud) copy of the alignment viewer; commit/push there by hand
uv run numrev gold ner --apply                             # (once) stratified NER gold sample → data/ner/gold.ls.json
uv run numrev train-set --apply                            # NER training set → data/ner/train.ls.json
uv run numrev train data/ner/train.ls.json --apply         # train GLiNER (remote GPU machine)
uv run numrev audit ner [--model DIR] [--sweep]            # NER audit on the reviewed gold → reports/ner/
uv run numrev audit crf                                    # CRF/feature audit on hand-corrected line CSVs → reports/crf/
uv run numrev gold alignment annuaires/<A> annuaires/<B> --apply   # (once) inversion gold to label → data/alignment/<A>__<B>.gold-inversions.csv
uv run numrev audit alignment data/alignment/<A>__<B>.gold-inversions.csv   # residual-rule precision + review reasons → reports/alignment/
uv run --group explorations jupyter nbconvert --to notebook --execute --inplace explorations/<nb>.ipynb   # exploratory notebooks
```

## Architecture

Detailed per-step documentation (French, for other devs): `docs/pipeline.md`; `README.md` is a short overview linking to it.

OCR is **out of scope** for this repo: it is run locally with Chandra in a separate project. A volume's starting state is its OCR output, `<volume>.ocr.json` (per-page `markdown` + `html` with `data-block-id` blocks), cut into page ranges with `jq` (`docs/pipeline.md`).

**Package layout (`src/numrev/`):** `cli.py` (entry point: tables `PIPELINE` / `TOOLS` of commands = name → module + summary; a module is imported only when its command runs, so `numrev --help` never loads torch/Dedupe/Streamlit; groups `align {nw,dedupe}`, `gold {ner,alignment}`, `audit {crf,ner,alignment}`); `pipeline/` (one module per step: `extract`, `label`, `tabulate`, `assemble`, `tag`, `align_nw`, `align_dedupe`, `join`); `viewers/` (`directory.py`, `alignment.py` Streamlit scripts, with the alignment viewer's `focus.py`, `context.py` + `assets/`, `storage.py`; `viewers/__init__.py` is the `numrev view` command and launches `streamlit run` without importing Streamlit); `devtools/` (`ner_gold`, `ner_dataset` (= `train-set`), `ner_train` (= `train`), `ner_audit`, `crf_audit`, `alignment_gold`, `alignment_audit`, `publish_viewer`); domain libraries `crf/`, `ner/`, `alignment/`; shared `command.py`, `paths.py`, `curation.py`, `document.py`, `titles.py`, `stats.py`, `reporting.py`. Steps vs tools: a **step** transforms volume data on the way to the deliverables (1–7); viewers, gold samplers, training and audits are **tools**. Tests import the package (`from numrev.pipeline.tabulate import …`); `tests/test_cli.py` builds every command's parser.

**Command convention (`command.py`):** each command module exposes `add_arguments(parser)` and `run(args)` (optional `DESCRIPTION` for the help). An expected failure raises `CommandError` (also from `require_file`, `require_dir`, `default_output`); `cli.main` prints `Erreur : …` and exits 1, and does the same for `CurationConflict` (`print_conflict`) — commands don't catch these themselves. Shared options: `add_apply_argument`, `add_force_argument`, `add_capture_arguments` (`--force`, `--no-capture`). Option names are consistent across commands — keep them so: the main input of steps 1–5 is the positional `input`; every output (file or report folder) is `-o/--output`, defaulting to a name derived from the input; `--model` is always a trained model folder (`train` takes `--base-model`); `--force` is the only way to overwrite an existing gold; `--gold`, `--root`, `--seed`, `--bootstrap`, `--threshold` (GLiNER: `ner.gliner.DEFAULT_THRESHOLD`), `--min-score`, `--batch-size`, `--margin` mean the same thing wherever they appear.

**File names (`paths.py`, the single place for them):** a *document* is a page range `<volume>.<range>` (no dots in volume or range names), in `annuaires/<volume>/<range>/`; each step appends its suffix: `.ocr.json` → `.lines.json` (1) → `.labeled.json` + `.label-session.json` (2) → `.lines.csv` (3) → `.entities.csv` + `.entities.report.txt` (4) → `.ner.csv` (5). `document_name(path)` strips a known suffix (unknown suffix = `ValueError`, no fallback), `step_path(path, suffix)` gives a sibling step file, `discover(root, suffix)` finds exactly `<root>/<volume>/<range>/<volume>.<range><suffix>` (sorted by path: sampling order depends on it), ignoring old copies lying in the folders. `Pair(left, right)` (`of_dirs`, `of_file` = file name up to its first dot) holds a pair's files: `data/alignment/<A>__<B>.patch.csv` / `.sections.csv` / `.training.json` / `.gold-inversions.csv`, outputs `annuaires/alignments/<A>__<B><suffix>` (`.nw.csv`, `.dedupe.csv`, final `.csv`, `.raw-sections[.dedupe].csv`, `….join.csv`). Other constants: `CURATION_DIR`, `NER_GOLD`, `NER_TRAIN`, `REPORTS_DIR` (`reports/crf|ner|alignment`), `MODELS_DIR`.

**Dry run by default (`command.py`):** every command that writes data files (steps 1–7, `gold`, `train-set`, `train`) computes and checks everything (curation conflicts, orphans included), lists the files it would write (new / replaced) and writes nothing; `--apply` writes. Route every write through `Writes.add(path, write_fn)` (it creates the parent folder) and end with `writes.finish(console)`; library functions take an optional `writes` (None = write, for tests; `load_section_alignment` without `writes` never rewrites its patch). `--force` keeps a single meaning: override a refusal (conflict, orphan, existing file), still only written with `--apply`. Exceptions: the annotator saves its session after every action (working state) but exports the annotated JSON only with `--apply`; `numrev train` without `--apply` validates and converts the data then stops before training. Audits (reports in `reports/`) and viewers have no `--apply`. Patch, training and section-patch paths are always the versioned ones (no path-override options).

Steps:

1. `numrev extract` — parses each block's HTML into Markdown lines; adds `data_blocks[].lines[]` (`uid`, `line_index`, `markdown`, `cle`) to every page; `cle` is the stable line key (see **Replayable human corrections**). Table cells are always exploded into separate lines; default output `<document>.lines.json`.
2. `numrev label` — interactive active-learning annotator (python-crfsuite). Labels lines `B-ENTRY`, `I-ENTRY`, `SUB-ENTRY`, `B-TITLE`, `I-TITLE`, `OUT OF SCOPE`, uncertain. Persists a resumable `<document>.label-session.json` after every action; exports each line's `prediction`/`provenance`/`probability`/`timestamp`. Probability is posterior-marginal argmax (not Viterbi) so it always matches the exported label.
3. `numrev tabulate` — flattens the JSON (annotated or raw) to one CSV row per line (`CSV_FIELDS`: `cle`, `uid`, …, `markdown`, `classe` (= JSON `prediction`), `corrige`, …, `empreinte`). For an annotated document the output `<document>.lines.csv` is also the hand-edited file (classes, text, `#` levels): curation protocol `lines` (`LINES_STEP`); a raw document is exported without patch.
4. `numrev assemble` — two roles. (a) Rebuilds logical entities from line labels using two independent open "tracks" (ENTRY, TITLE) that stay open across `OUT OF SCOPE` / other-family lines until a new `B-` root, and gives each a deterministic `uuid` (uuid5 of document name + the `cle` of its **root line**; never the text, the page or the continuations; the entity's `cle` column keeps its composition `k1,k2,…`). Reads class column `classe`, skips `SUPPRIMÉE` rows, drops the line curation columns `corrige`/`empreinte`. (b) Sets `parent_uuid` on every row (TITLE, ENTRY and OUT OF SCOPE): title level = number of leading `#` (no `#` = deepest level, flagged in the report); a TITLE's parent is the last preceding title of strictly lower level, any other row's the last preceding title; top-level titles and rows before any title get the nil UUID `ROOT_UUID` (single root shared by all documents). Writes `*.entities.csv` and a `*.entities.report.txt` (indented title tree with recursive and direct ENTRY counts per title; orphan continuations, titles without `#`, alphabetical-order breaks reset at each TITLE, unknown classes).
5. NER on ENTRY entities (conventions: `docs/guide_annotation_ner.md`):
   - `numrev tag` — runs the trained model on an entities CSV, inserting `tagged_text` and per-class counts after the `entity` column. Requires `<model>/ner_config.json` (labels); feeds normalized text and maps spans back to the raw `markdown`. Also writes `ner_confidence` (min span score) and `ner_suspect` (review-priority reasons from `numrev/ner/suspicion.py`: model score + generic structural checks, no corpus-specific lexicon); `numrev audit ner` reports the flag's coverage and recall of errors. The output `*.ner.csv` is also the hand-edited file (`tagged_text`, `parent_uuid`): curation protocol `ner` (`NER_STEP`), captured before the model loads, reapplied by `uuid`; a correction whose entity text changed upstream, whose entity or parent title vanished panics; span counts are recomputed on corrected rows.
   - `numrev view directory` — Streamlit viewer of a volume's final NER CSV (sections from heading levels, span colours, suspect filters, per-section stats).
   - `numrev train-set` — builds the versioned training set `data/ner/train.ls.json` (needs local `annuaires/`) from the NER CSVs (`*.ner.csv`; `numrev/ner/corpus.py` exposes corrected rows as source `ner_curated` too), gold texts excluded, shape-stratified (√) sampling. The CSVs must follow the annotation guide: a model relearns its data's convention errors.
   - `numrev train` — trains a GLiNER-bi model (run on the remote GPU machine) on one or more Label Studio JSON files (converts char spans → whitespace-token spans, auto-computes `max_width`); always on Markdown-normalized text; excludes gold texts, validates on a per-page split; writes `<model>/ner_config.json` (labels). Base model stays GLiNER-bi: a fine-tuned `knowledgator/gliner-relex-large-v0.5` tied it on the dev gold (27 errors each) at 3× the size (`docs/experience_gliner_relex.md`); relex models are supported (`numrev/ner/gliner.predict_entities` asks for entities only).

6. Alignment of two editions; shared loading in `alignment/pair.py` (`pair_of_dirs` / `pair_of_file`, `load_pair` = both volumes + section correspondence, panics on section-patch orphans unless `--force`; `refuse=False` for the gold sampler and the audit) and `alignment/patch.py` (`load_patch`, `declared_unmatched`, `orphan_descriptions`).
   - `numrev align dedupe` — aligns the ENTRY rows of two **complete** directories with Dedupe `RecordLink` (one-to-one). `numrev/alignment/records.py` loads a volume folder: its page-range subfolders sorted by first page, each read from its own `<volume>.<range>.ner.csv` (missing → error). Fields: `section` (ancestor title of level 2, else 1, via `parent_uuid`, so no inheritance across ranges; accent/punctuation-insensitive key), `subj` (SUBJ spans, Markdown-normalized), `text` (full normalized text); lowercased for Dedupe. Labels come from `dedupe.console_label` on first run or `--label`, saved to `data/alignment/<left>__<right>.training.json` (versioned) and reused. Outputs in `annuaires/alignments/`: `<left>__<right>.dedupe.csv` (raw Dedupe links) and `<left>__<right>.csv` (final = Dedupe + manual patch); columns `left_file, left_uuid, right_uuid, right_file, score, source` (`dedupe`/`manuel`, empty score for hand pairs) then snapshot columns for review (`left_section, right_section` = readable titles `Record.section_title`, `left_tagged_text, right_tagged_text`); unmatched entries are those absent from it. Manual corrections live in the versioned `data/alignment/<left>__<right>.patch.csv` (`numrev/alignment/patch.py`): a row with both uuids forces a pair, a row with one uuid declares it unmatched; optional column `certitude` (empty or `incertaine`; an uncertain pair gets source `manuel-incertain`, exported as `certitude = incertaine`); the patch wins over Dedupe (any Dedupe link touching a patched uuid is dropped). Lost uuids (upstream re-segmentation) are re-anchored by unique (section key, normalized text) match and the patch is rewritten; otherwise the row is an orphan (kept, not applied; `numrev align dedupe`, `numrev align nw` (section patch) and `numrev join` panic on orphans unless `--force`; the viewer only shows them). `--patch-only` reapplies the patch to the existing `.dedupe.csv`. `numrev view alignment` picks a `*.dedupe.csv` or `*.nw.csv`, reloads both volumes from the pair name (`<left>__<right>` = volume folders), applies the patch **plus the pending decision journal** in memory (recomputed after each decision, built to scale to 100 k+ entries per side: `load_base` = journal-independent part cached once; `review.Reviewer` memoizes review results per segment and recomputes only segments whose links/declared uuids changed (same result as `review`, tested); `export.natural_order` + `build_rows` are numpy-vectorized, text columns kept `object` (Arrow string conversion is the slowest step); `EntryStates` computes entry states lazily; ~0.05 s per decision on 1807/1808, ~0.7 s on a 10× duplicated bench of ~170 k / 160 k entries — never reintroduce per-row pandas access (`itertuples`, `.at`) over all rows), and has one cursor (current row, `st.session_state["cursor"]` = (left uuid, right uuid); rows in natural order: pairs and left-only rows by left order, a right-only row after the pair holding the preceding paired right entry) and one task queue (`task_levels` / `task_queue`, sidebar « Tâches de relecture »: candidates, medium, high by default; lone entries, low-score pairs optional; decided rows excluded unless « Revoir aussi ») shared by two views: **Documents**, the default (`viewers/context.py` + `viewers/assets/context.{js,css}`: both volumes in their own order with TITLE/OUT OF SCOPE rows (`records.load_lines`), 200 lines around the cursor, current section after each list name (selected entry's if visible, else top visible line; `context.section_before` above the window), SVG links (clickable; dash = certainty: solid sure, dashed uncertain (`EntryState.uncertain`: `manuel-incertain` or automatic level ≥ 1), red dashed candidate; colour = origin: grey automatic, dark human; inversions = yellow halo), task markers « ! », legend above the columns; click an entry or a link = current row, kept still on screen; a task reached by N/P, search or section jump is centred; the loupe on the current link (or the tab) opens the zoom, there is no separate zoom button; decision buttons above the diff; « ⇄ Autre partenaire… » = pairing mode, only entries of the paired segment clickable; « ⋯ » grows the clicked column by 10 lines (the other one up to their partners) keeping the view still, « Page » slides the clicked column by a page and the other one shows every partner of that page (`context.follow`, at most 3 pages); explicit bounds kept in `VIEWPORT`, reset when the cursor moves; search; uuid copy on titles) and **Relecture**, the zoom (`viewers/focus.py`: character diff, closest alternatives with `Review.rivals` flagged, note, auto-advance). Shared task bar: P/N tasks, Ctrl+Z undo; tabs switch views; decisions V/I/X/A. Theme: classic GitHub Primer greys + blue accent, NER spans tab10 blue/orange/green, light and dark, in `viewers/assets/theme.toml`, passed as `streamlit run` options by `numrev view alignment` (`viewers.theme_options`), published as `.streamlit/config.toml`; the same palette in `context.css` and `focus.py`. No table view; indicators and the sections table are in the « Synthèse » dialog. Decisions (`alignment/decisions.py`): an ordered journal replayed over the versioned patch (a decision drops the patch lines touching its uuids then adds its own, so `validate` always holds; « pas la même entrée » = both uuids declared unmatched, the patch format has no negative pair), kept in the browser's `localStorage` through an invisible v2 component (`viewers/storage.py`; Python never sends a journal before the saved one is restored). **Enregistrer** (only when `NUMREV_PATCH_WRITABLE=1`, set by `numrev view`) writes the full patch with `write_patch` and clears the journal; **Télécharger le patch** (`patch.patch_csv`, same bytes) is the hosted copy's only output. The section patch stays hand-edited (uuid copy buttons). v2 component JS functions are re-run on every `data` change (cleanup only on unmount): render idempotently. Test it with a wrapper that overrides `numrev.paths.ALIGNMENTS_DIR` / `ALIGNMENT_DATA_DIR` / `ANNUAIRES_DIR`, never in the real folders (or headless with `streamlit.testing.v1.AppTest`, where v2 components don't run JS). Dedupe 3.0.3 needs `btrees<6` (BTrees 6 dropped `byValue`); `prepare_training` takes a few minutes on ~17 k × 16 k entries.
   - `numrev align nw` — training-free alternative (algorithm in `alignment/nw.py`: `Params`, `align`, `residual_pairs`, `windows`; the command only loads, writes and prints), to be compared with Dedupe once alignments are curated (method and maths: `docs/alignement_ordonne.md`). Uses the entries' order: sections (always in the same order across editions) are aligned by Needleman-Wunsch on Jaro-Winkler of their key; then, per paired section group only (`segments` = `alignment.groups`; entries of unpaired sections are never matched — link the sections in the section patch first): Needleman-Wunsch (zero gap cost, maximizes Σ(sim − threshold)) whose pairs with sim ≥ 0.9 become **anchors**; a residual pass (`linear_sum_assignment`, sim ≥ 0.85) on entries outside the NW pairs keeps local inversions; then, between consecutive anchors (residual entries removed), a **pair-HMM** (`numrev/alignment/pair_hmm.py`, states M/X/Y, forward-backward in log space) keeps pairs with posterior > 0.5, so a flanked pair of middling similarity can be matched. Emissions are fixed and estimated out of context — `p(sim | same)` from pairs with identical SUBJ unique on both sides, `p(sim | different)` from anchors' neighbours (i, j±d) — with the likelihood ratio forced non-decreasing; EM only learns transitions (letting EM learn `p(sim | same)` is non-identifiable: it turns replacements into matches). `sim = w·JaroWinkler(subj) + (1−w)·Indel(text)` (text only without SUBJ), same fields as Dedupe (`dedupe_records`), via `rapidfuzz.cdist`. Writes `annuaires/alignments/<left>__<right>.nw.csv` (same columns; `source` = `nw` anchor / `nw-contexte` (score = posterior) / `nw-residuel`; `--no-context` = plain NW), never applies the patch, and prints the estimated transitions and its agreement with the `.dedupe.csv`. ~12 s on 1807/1808. `numrev view alignment` lists both `*.dedupe.csv` and `*.nw.csv`.
   - **Review reasons** (`numrev/alignment/review.py`, shared by the viewer, the export and `numrev audit alignment`): the alignment itself is unchanged; after the fact, per segment (same similarity as `align nw`, `segment_entries`), each link gets reasons — `déduite des voisines (p < 0,9)` (`nw-contexte` posterior < 0.9), `homonyme proche` (`nw`/`nw-residuel`/`dedupe` link with another entry of the segment within `margin` 0.05 of similarity) — and **unmatched candidates** (source/status `candidate`, reason `candidate non appariée`, never a link: two unmatched entries, mutual best in the segment, sim in [τ ; θr[ of `alignment.nw.Params`, never a patch-declared uuid) are added. Ordinal uncertainty `LEVEL_LABELS` = `faible` (no reason) / `moyenne` (one) / `forte` (candidate, several reasons or posterior < 0.7) — not a probability, nothing learnt on a volume; keep the three labels on that single uncertainty axis (no "à relire" / "très incertaine"). Viewer: the inspector / review card shows an explicit status (`✓ appariée automatiquement` / `relue` / `relue, incertaine`, `? candidate non appariée`, `✗ sans correspondance`) + score + uncertainty badge and reasons (the `candidate non appariée` reason is not repeated under the candidate status); in the documents, a « ! » marks review tasks (orange medium, red high or candidate); « Synthèse » dialog = indicators + sections table (paired section groups then lone sections, entries / matched / rate per side, uuids); `CANDIDATE` kind in `numrev/alignment/export.py`, not counted as matched. Sidebar from common to fine: alignment, Décisions (journal), Tâches de relecture, Export, then a collapsed "Réglages fins de la relecture" expander (candidate threshold, homonym margin — read first via `st.sidebar.container()` placeholders because they feed the cached computation). Conventions: `docs/guide_relecture_alignement.md`. Why not a finer residual pass: on the labelled 1807/1808 inversion gold the 0.85 rule is ~93 % precise, the recoverable gain is ≤ 0.5 % of pairs and needs external knowledge, displacement (absolute or relative to section size) carries no signal, and unsupervised displacement priors failed (`docs/alignement_ordonne.md` § 6.1). For a new pair of directories, label a small gold and run the audit before trusting the thresholds.
   - **Section correspondence** (`numrev/alignment/sections.py`, shared by `numrev align dedupe`, `numrev align nw` and `numrev view alignment`): a section = contiguous ENTRY run of one `Record.section`, identified by its TITLE uuid (`Record.section_uuid`; one title per section key in 1807/1808). Sections are aligned by Needleman-Wunsch on Jaro-Winkler of their key (threshold 0.8, `numrev/alignment/sequence.py`), after the hand-edited, versioned patch `data/alignment/<left>__<right>.sections.csv` (`left_uuid, right_uuid, left_title, right_title, note`): pair rows are linked and their connected components form 1-1/1-N/N-M groups (removed from the automatic alignment; NW aligns a manual group's concatenated entries, free of order), a single-uuid row declares a section unmatched (never pooled into a NW gap). Lost uuids are re-anchored by unique `clean_title` of the recorded title (patch rewritten by the commands, not by the viewer), else orphan. Dedupe compares `section` through `canonical_keys` (group → key of its first left section, idempotent), applied to the data and, on read, to the training JSON pairs (`canonical_training`), so no relabelling. `numrev align dedupe --raw-sections` keeps the original per-volume keys, writing `<left>__<right>.raw-sections[.dedupe].csv`, so both variants can be compared on a gold (the viewer derives the pair from the file name up to its first dot). **Entries are only ever matched between paired sections** (so recall depends on the section patch; the inversion gold, drawn within segments, cannot see entries of unpaired sections — `numrev audit alignment` lists them in its section 4, 42 entries of 1808 on 1807/1808): `restrict_to_corresponding(links, left, right, alignment)` drops any other link (Dedupe produces some: 16 on 1807/1808; also patch pairs, reported) in `numrev align dedupe` (raw and final outputs, also `--patch-only`), the viewer ("Liens écartés" KPI + expander for patch pairs) and the export.
7. `numrev join` — readable join of the two aligned volumes for data users (historians): takes any alignment CSV (`.dedupe`/`.nw`/final), reloads both volumes, applies the entry patch in memory (never rewritten; `--no-patch`), writes `<input>.join.csv` (`--excel`: `;` + UTF-8 BOM; `--candidates` adds unmatched-candidate rows; `--margin` = homonym margin). One row per pair / unmatched entry in the viewer's natural order; French columns `statut, score, methode, certitude, niveau_incertitude, motifs_relecture`, then per side `gauche_`/`droite_` + `volume, page, rubrique, texte, sujet, description, adresse, texte_balise, uuid` (span texts Markdown-normalized, several spans of a class joined by ` | `). `numrev/alignment/export.py` holds the natural-order join (`natural_rows`, also used by the viewer's table) and the CSV export; the viewer's sidebar button exports the currently filtered/sorted rows in the same format.

**Replayable human corrections (`numrev/curation.py`; user guide with examples: `docs/guide_curation.md` — keep it in sync with the protocol):** one protocol for every hand-curated step. A curated step's output CSV is both machine output and the file edited by hand (Excel/OpenRefine, whole-document context); each row has a stable key, editable fields, `corrige` (`oui` = corrected or validated as is) and `empreinte` (hash of the machine's editable fields). Each run: (1) **capture** — if the output exists, its `corrige = oui` rows rewrite the versioned patch `data/curation/<document>.<step>.patch.csv` (git is the safety copy); (2) generate; (3) **apply** the patch (patch wins). It succeeds entirely or writes nothing: `CurationConflict` (**panic**) on an edited row without `corrige` (fingerprint mismatch), a correction that no longer applies (key gone, NER text changed upstream, parent title gone), or a machine line erased or moved in the lines file. `--force` takes the new machine output for those rows (also how to cancel a correction: clear `corrige`, rerun with `--force`); `--no-capture` restarts from the versioned patch (always the versioned path, no override). Lines step: delete = class `SUPPRIMÉE` (`DELETED_CLASS`); a row added without key or duplicated gets `<base key>+n`, the patch keeps its position (`apres`); move = `SUPPRIMÉE` + keyless copy (machine lines keep OCR order). Line key `cle` = 12-hex sha1 of the frozen-normalized OCR text (`normalize_text`: NFC, nbsp, whitespace — never change it) + `~n` from the 2nd identical text; independent of page and block segmentation, unlike `uid`. Alignment patches (`data/alignment/`) follow the same rules (patch wins, orphans panic, `--force`) but are not captured: the entry patch is written by the alignment viewer (decisions), the section patch by hand; their atomic writes go through `numrev/curation.write_csv`. Data commits stay separate from code commits (prefix `données:`); commands and viewers never commit.

**Shared code** (domain libraries, imported as `numrev.…`):
- `curation.py` — the replayable-corrections protocol above (`Step`, `Curation` — patch path defaults to `paths.curation_patch` —, `CurationConflict`, `line_keys`, `fingerprint`, `refuse_orphans`, `read_csv`, `read_dataclasses` for the hand-edited alignment patches, atomic `write_csv`).
- `document.py` — the pages → `data_blocks` → `lines` JSON shape, validated and iterated in one place (`iter_line_locations`), used by `label`, `tabulate` and the CRF core. Change the schema there.
- `stats.py` (page bootstrap, intervals, calibration, ROC AUC, review capture) and `reporting.py` (Markdown helpers, `write_table` for report CSVs) are shared by the audits; `viewers/common.py` (`text_mask`, page sizes) by the two viewers.
- `alignment/records.py` — volume loading (`load_volume` = ENTRY records, `load_lines` = every printed line), Dedupe fields, entry similarity (`similarity_matrix`) and link CSV I/O; `alignment/decisions.py` — the viewer's decision journal; `alignment/pair.py` — pair loading and console summaries (`print_matched`, `print_sections`); `alignment/nw.py` — the order-based method; `alignment/review.py` — review reasons, uncertainty level and unmatched candidates; `alignment/patch.py` — the manual-correction patch of entries; `alignment/export.py` — natural-order join and readable CSV export; `alignment/sections.py` — section correspondence, its patch, the entry segments (`segments`, `segment_entries`, paired groups only) and `restrict_to_corresponding`; `alignment/sequence.py` — Needleman-Wunsch; `alignment/pair_hmm.py` — pair-HMM.
- `titles.py` — heading level, readable text of TITLE rows and the tree root `ROOT_UUID`, shared by `assemble`, `tag`, `alignment/records.py` and the directory viewer.
- `ner/` — NER: spans and their representations (`spans.py`), HTML rendering of spans shared by both viewers (`html.py`), typographic shapes (`shapes.py`), NER CSV reader (`corpus.py`: `discover(root, ENTITIES)` + sibling `.ner.csv`) and Label Studio text sets used for exclusions (`ls_texts`), gold metrics (`metrics.py`), review-priority reasons (`suspicion.py`), model loading/prediction (`gliner.py`).
- `crf/` — CRF core. `labels.py` (line classes, also used by `assemble`); `features.py` defines named feature groups (`PRODUCTION_GROUPS` = exactly what the annotator uses, computed on Markdown-normalized text via `normalize_line` — emphasis markers, leading `#` and trailing spaces stripped, italic kept as the `italic` bucket feature; `LEGACY_GROUPS` reproduces the pre-v2 production set bit-for-bit for comparison (`production_v1` in the audit); `CANDIDATE_GROUPS` and `PLACEBO_GROUPS` are only evaluated by the audit). `model.py` wraps python-crfsuite training/marginals, `active_learning.py` holds `SourceLine`/`load_json_lines`/`ActiveCRF`; `pipeline/label.py` keeps only the Rich UI, sessions and CLI.
- Changing production features changes annotator behaviour; to try a feature, add a candidate group and run the audit instead.

**CRF audit (`numrev audit crf`):** uses the hand-corrected `<document>.lines.csv` (column `classe`, `SUPPRIMÉE` rows excluded; original model labels read from the sibling `<document>.labeled.json`) as silver ground truth. `numrev/crf/silver.py` takes observations from the sibling `<document>.lines.json` (what the annotator saw) and attaches curated labels by the line key `cle` (both JSONs and the CSV must carry it; lines added by hand have no observation and are ignored) — curators also edited text (notably `#` heading markers), so computing features on the curated CSV text would leak labels. Curated labels differ from the original model predictions on only ~0.2 % of lines, so absolute scores are optimistic. `numrev/crf/evaluation.py` runs page-contiguous within-document CV and leave-one-volume-out CV in parallel processes, with page-level (cluster) bootstrap; placebo feature groups give the noise floor used for verdicts.

**NER audit (`numrev audit ner`):** Ground truth is the hand-reviewed stratified, weighted gold `data/ner/gold.ls.json` (Label Studio; committed; `dev`/`test` split fixed — never tune on `test`). Hand-corrected rows of the `*.ner.csv` files (`corrige = oui`) are only a partial review: silver, not ground truth. `numrev audit ner` only evaluates the systems it is given (`--model`, `--predictions`); on the dev split one `courant` entry weighs ~1.5 points, so also compare raw error counts. Annotations are compared on Markdown-normalized text (`normalize_markdown` + `project_spans`); join NER CSVs to entities CSVs on `uid`; exclude training data by normalized text, not uid.

The line-level BIO classes (steps 2–4) and the span classes `SUBJ/DESC/ADDR` (step 5) are separate label spaces. If you rename a line class, update `crf/labels.py` (`assemble` reads its classes from there) — unknown classes are treated as out-of-scope and only flagged in the report.

`devtools/alignment_gold.py` (`numrev gold alignment`) is the inversion gold sampler: NW-unmatched pairs crossing ≥ 1 ordered pair, best crossed partner per left entry, strata displacement × similarity, weight = stratum size / drawn; hand-labelled column `meme_entree` = `OUI` / `NON` / `INCERTAIN` (never "unsure"); never overwritten without `--force`. It exists because unsupervised estimates of a displacement-aware residual pass failed on 1807/1808: the identical-SUBJ sample misses moved entries (they mostly moved because their name changed spelling), and letting EM learn p(sim | different) diverges. Scripts that were no longer used (`main.py`, the LLM pre-annotator `autoclassify_labelstudio.py`) were deleted; the git tag `avant-menage` points to the last commit that has them (`git show avant-menage:<file>`).

`explorations/` holds exploratory notebooks (deps in the `explorations` dependency group: Jupyter, matplotlib; see `explorations/README.md`); they run from `explorations/` or the repo root and are committed with their outputs. `consolidation_adresses_1807_1808.ipynb` classifies the ADDR fields of aligned 1807/1808 pairs (équivalence / changement de numéro / déménagement / adresse complexe, plus sans numéro / adresse absente; street names normalized, fuzzy threshold ε) and exports `<join>.consolidated.csv`.

**Hosted viewer (`numrev publish-viewer`, `devtools/publish_viewer.py`):** the Streamlit Cloud copy lives in a separate deployment repo (`../alignment-viewer`, GitHub `HueyNemud/directories-alignment-viewer`), a published snapshot regenerated by this command, never edited by hand. It copies verbatim the static import closure of `numrev.viewers.alignment` plus `viewers/assets/`, the published pairs' `*.ner.csv`, alignment outputs, `.sections.csv` and `.patch.csv`, and generates `streamlit_app.py`, pinned `requirements.txt`, `README.md` (source commit) and the manifest `.numrev-publish.json` (only files from the previous manifest are ever deleted). Deliberately not extracted as a package: the viewer is a client of the still-evolving alignment code. **Dependency boundary:** the viewer's closure may only import numpy, pandas, rapidfuzz, rich, scipy, streamlit (`ALLOWED`, enforced by `tests/test_publish_viewer.py`) — never import torch/GLiNER/Dedupe/crfsuite at module level in `alignment/`, `ner/html.py`, `ner/spans.py`, `titles.py`, `paths.py`, `curation.py`, `command.py`, `crf/features.py`, `crf/labels.py`. It refuses uncommitted changes under `src/numrev` (`--force`).

## Data

`annuaires/` (per-volume working folders), `*.pdf`, `*.gpkg` and `uv.lock` are git-ignored. Pipeline outputs live next to their inputs in `annuaires/<volume>/<range>/`, alignment outputs in `annuaires/alignments/`. Human decisions live in versioned `data/` (`data/curation/` patches of steps 3 and 5 `<document>.lines.patch.csv` / `.ner.patch.csv`, `data/alignment/`, `data/ner/`). Audit reports go to `reports/`.

**Format changes: ask, don't default to backward compatibility.** Before a change that alters the shape of data files (JSON/CSV columns, keys, uuids, file names, patch formats), ask the user which way to go: (a) keep the code backward compatible with the old files, or (b) migrate the existing data once (a one-off script, dry run first, backup of the git-ignored `annuaires/` files it touches) and make the code accept **only** the new format (fail loudly on old files, no fallback branches). Default recommendation: (b) — compatibility branches pile up and make the code heavier, and git keeps every former version. After a migration, delete the one-off script and the obsolete files/options it made unnecessary, and remove "formerly…" / "older file" mentions from code, docs and this file.
