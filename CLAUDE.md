# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Pipeline turning scanned historical Paris directories (annuaires, early 1800s) into structured entries (ENTRY) nested under a title hierarchy (TITLE), then splitting each entry into NER spans `SUBJ` / `DESC` / `ADDR`. Code, comments, CLI help and README are in **French**; keep new code consistent with that.

## Commands

Managed with `uv` (Python ≥ 3.12). No linter/formatter or pytest is configured.

```bash
uv sync                                                    # install deps into .venv
uv run python -m unittest discover -s tests                # all tests (unittest, not pytest)
uv run python -m unittest tests.test_export_lines_csv      # one test module
uv run python -m unittest tests.test_export_lines_csv.<Class>.<test_name>   # one test
uv run streamlit run tools/display_directory.py            # viewer for a volume's final NER CSV (*.merged.ner.csv)
uv run align_directories.py annuaires/<A> annuaires/<B> [--label] --apply   # Dedupe alignment of two editions
uv run align_directories.py annuaires/<A> annuaires/<B> --sans-dedupe --apply   # reapply the manual patch, no Dedupe
uv run align_directories.py annuaires/<A> annuaires/<B> --raw-sections --apply   # Dedupe variant with per-volume section keys (for comparison)
uv run align_directories_nw.py annuaires/<A> annuaires/<B> --apply  # order-based alternative (Needleman-Wunsch), no training
uv run streamlit run tools/display_alignment.py            # alignment viewer (read-only; copy buttons for the hand-edited patch; CSV export)
uv run tools/export_alignment.py annuaires/alignements/<A>__<B>.nw.csv [--excel] --apply   # readable joined CSV for data users
uv run tools/sample_alignment_gold.py annuaires/<A> annuaires/<B> --apply   # (once) stratified sample of candidate inversions to label → data/alignement/<A>__<B>.gold-inversions.csv
uv run tools/audit_alignment_review.py data/alignement/<A>__<B>.gold-inversions.csv   # residual-rule precision + review reasons on the gold → rapports/audit_alignement/
uv run audit_crf_features.py                               # CRF/feature audit on hand-corrected line CSVs → rapports/audit_crf/
uv run tools/sample_ner_gold.py --apply                    # (once) stratified NER gold sample → data/ner/gold.ls.json
uv run audit_ner.py [--model DIR] [--sweep]                # NER audit on the reviewed gold → rapports/audit_ner/
uv run --group explorations jupyter nbconvert --to notebook --execute --inplace explorations/<nb>.ipynb   # exploratory notebooks
```

Tests import the top-level scripts as modules, so run them from the repo root.

## Architecture

Detailed per-step documentation (French, for other devs): `docs/pipeline.md`; `README.md` is a short overview linking to it.

OCR is **out of scope** for this repo: it is run locally with Chandra in a separate project. A volume's starting state is its OCR output, `<nom>.ocr.json` (per-page `markdown` + `html` with `data-block-id` blocks) and `<nom>.ocr.md`, e.g. in `annuaires/1808_AD75-PER292/`.

Each step is a standalone CLI script at the repo root (argparse, `rich` console output, `-o/--output` defaulting to a name derived from the input), chained by file.

**Dry run by default (`lib/cli.py`):** every command that writes data files (pipeline steps 1–6, `tools/export_alignment.py`, `tools/sample_*_gold.py`, `tools/build_ner_training.py`, `tools/train_gliner.py`) computes and checks everything (curation conflicts, orphans included), lists the files it would write (new / replaced) and writes nothing; `--apply` (`add_apply_argument`) writes. Route every write through `Writes.add(path, write_fn)` and end with `writes.finish(console)`; library functions take an optional `writes` (None = write, for tests; `load_section_alignment` without `writes` never rewrites its patch). `--force` keeps a single meaning: override a refusal (conflict, orphan, existing file), still only written with `--apply`. Exceptions: the annotator saves its session after every action (working state) but exports the annotated JSON only with `--apply`; `train_gliner.py` without `--apply` validates and converts the data then stops before training. Audits (reports in `rapports/`) and viewers have no `--apply`. Patch, training and section-patch paths are always the versioned ones (no path-override options).

Steps:

1. `extract_chandra_lines.py` — parses each block's HTML into Markdown lines; adds `data_blocks[].lines[]` (`uid`, `line_index`, `markdown`, `cle`) to every page; `cle` is the stable line key (see **Replayable human corrections**). Table cells are always exploded into separate lines; default output `<nom>.ocr.lines.json`.
2. `annotate_lines_crf.py` — interactive active-learning annotator (python-crfsuite). Labels lines `B-ENTRY`, `I-ENTRY`, `SUB-ENTRY`, `B-TITLE`, `I-TITLE`, `OUT OF SCOPE`, uncertain. Persists a resumable `.crf-session.json` after every action; exports each line's `prediction`/`provenance`/`probability`/`timestamp`. Probability is posterior-marginal argmax (not Viterbi) so it always matches the exported label.
3. `export_lines_csv.py` — flattens the JSON (annotated or raw) to one CSV row per line (`CSV_FIELDS`: `cle`, `uid`, …, `markdown`, `classe` (= JSON `prediction`), `corrige`, …, `empreinte`). For an annotated document the output `*.ocr.lines.annotated.csv` is also the hand-edited file (classes, text, `#` levels): curation protocol `lines` (`LINES_STEP`); a raw document is exported without patch.
4. `build_entity_tree.py` — two roles. (a) Rebuilds logical entities from line labels using two independent open "tracks" (ENTRY, TITLE) that stay open across `OUT OF SCOPE` / other-family lines until a new `B-` root, and gives each a deterministic `uuid` (uuid5 of document name + the `cle` of its **root line**; never the text, the page or the continuations; the entity's `cle` column keeps its composition `k1,k2,…`). Reads class column `classe`, skips `SUPPRIMÉE` rows, drops the line curation columns `corrige`/`empreinte`. (b) Sets `parent_uuid` on every row (TITLE, ENTRY and OUT OF SCOPE): title level = number of leading `#` (no `#` = deepest level, flagged in the report); a TITLE's parent is the last preceding title of strictly lower level, any other row's the last preceding title; top-level titles and rows before any title get the nil UUID `ROOT_UUID` (single root shared by all documents). Writes `*.merged.csv` and a `*.merged.report.txt` (indented title tree with recursive and direct ENTRY counts per title; orphan continuations, titles without `#`, alphabetical-order breaks reset at each TITLE, unknown classes).
5. NER on merged ENTRY rows (conventions: `docs/guide_annotation_ner.md`):
   - `infer_gliner.py` — runs the trained model on a merged CSV, inserting `tagged_text` and per-class counts after the `entity` column. Requires `<model>/ner_config.json` (labels); feeds normalized text and maps spans back to the raw `markdown`. Also writes `ner_confidence` (min span score) and `ner_suspect` (review-priority reasons from `lib/ner/suspicion.py`: model score + generic structural checks, no corpus-specific lexicon); `audit_ner.py` reports the flag's coverage and recall of errors. The output `*.merged.ner.csv` is also the hand-edited file (`tagged_text`, `parent_uuid`): curation protocol `ner` (`NER_STEP`), captured before the model loads, reapplied by `uuid`; a correction whose entity text changed upstream, whose entity or parent title vanished panics; span counts are recomputed on corrected rows.
   - `tools/display_directory.py` — Streamlit viewer of a volume's final NER CSV (sections from heading levels, span colours, suspect filters, per-section stats).
   - `tools/build_ner_training.py` — builds the versioned training set `data/ner/train.ls.json` (needs local `annuaires/`) from the NER CSVs (`*.ner.csv`; `lib/ner/corpus.py` exposes corrected rows as source `ner_curated` too), gold texts excluded, shape-stratified (√) sampling. The CSVs must follow the annotation guide: a model relearns its data's convention errors.
   - `tools/train_gliner.py` — trains a GLiNER-bi model (run on the remote GPU machine) on one or more Label Studio JSON files (converts char spans → whitespace-token spans, auto-computes `max_width`); always on Markdown-normalized text; excludes gold texts, validates on a per-page split; writes `<model>/ner_config.json` (labels). Base model stays GLiNER-bi: a fine-tuned `knowledgator/gliner-relex-large-v0.5` tied it on the dev gold (27 errors each) at 3× the size (`docs/experience_gliner_relex.md`); relex models are supported (`lib/ner/gliner.predict_entities` asks for entities only).

6. `align_directories.py` — aligns the ENTRY rows of two **complete** directories with Dedupe `RecordLink` (one-to-one). `lib/alignment.py` loads a volume folder: its page-range subfolders sorted by first page, each read from its own `<volume>.<range>` + `NER_SUFFIX` file (`*.ocr.lines.annotated.merged.ner.csv`; missing → error). Fields: `section` (ancestor title of level 2, else 1, via `parent_uuid`, so no inheritance across ranges; accent/punctuation-insensitive key), `subj` (SUBJ spans, Markdown-normalized), `text` (full normalized text); lowercased for Dedupe. Labels come from `dedupe.console_label` on first run or `--label`, saved to `data/alignement/<left>__<right>.training.json` (versioned) and reused. Outputs in `annuaires/alignements/`: `<left>__<right>.dedupe.csv` (raw Dedupe links) and `<left>__<right>.csv` (final = Dedupe + manual patch); columns `left_file, left_uuid, right_uuid, right_file, score, source` (`dedupe`/`manuel`, empty score for hand pairs) then snapshot columns for review (`left_section, right_section` = readable titles `Record.section_title`, `left_tagged_text, right_tagged_text`); unmatched entries are those absent from it. Manual corrections live in the versioned `data/alignement/<left>__<right>.patch.csv` (`lib/alignment_patch.py`): a row with both uuids forces a pair, a row with one uuid declares it unmatched; optional column `certitude` (empty or `incertaine`; an uncertain pair gets source `manuel-incertain`, exported as `certitude = incertaine`); the patch wins over Dedupe (any Dedupe link touching a patched uuid is dropped). Lost uuids (upstream re-segmentation) are re-anchored by unique (section key, normalized text) match and the patch is rewritten; otherwise the row is an orphan (kept, not applied; `align_directories.py`, `align_directories_nw.py` (section patch) and `tools/export_alignment.py` panic on orphans unless `--force`; the viewer only shows them). `--sans-dedupe` reapplies the patch to the existing `.dedupe.csv`. `tools/display_alignment.py` (read-only) picks a `*.dedupe.csv`, reloads both volumes from the pair name (`<left>__<right>` = volume folders), applies the patch in memory, and shows one table in natural order (pairs and left-only rows by left order; a right-only row goes after the pair holding the preceding paired right entry), filterable by row kind. Copy buttons (`st.html` with `unsafe_allow_javascript`) put an uuid or a ready-made patch line on the clipboard; the patch itself is edited by hand. Test it with a wrapper that overrides `ALIGNMENTS_DIR`/`PATCH_DIR`, never in the real folders. Dedupe 3.0.3 needs `btrees<6` (BTrees 6 dropped `byValue`); `prepare_training` takes a few minutes on ~17 k × 16 k entries.
   - `align_directories_nw.py` — training-free alternative, to be compared with Dedupe once alignments are curated (method and maths: `docs/alignement_ordonne.md`). Uses the entries' order: sections (always in the same order across editions) are aligned by Needleman-Wunsch on Jaro-Winkler of their key; then, per paired section group only (`segments` = `alignment.groups`; entries of unpaired sections are never matched — link the sections in the section patch first): Needleman-Wunsch (zero gap cost, maximizes Σ(sim − threshold)) whose pairs with sim ≥ 0.9 become **anchors**; a residual pass (`linear_sum_assignment`, sim ≥ 0.85) on entries outside the NW pairs keeps local inversions; then, between consecutive anchors (residual entries removed), a **pair-HMM** (`lib/pair_hmm.py`, states M/X/Y, forward-backward in log space) keeps pairs with posterior > 0.5, so a flanked pair of middling similarity can be matched. Emissions are fixed and estimated out of context — `p(sim | same)` from pairs with identical SUBJ unique on both sides, `p(sim | different)` from anchors' neighbours (i, j±d) — with the likelihood ratio forced non-decreasing; EM only learns transitions (letting EM learn `p(sim | same)` is non-identifiable: it turns replacements into matches). `sim = w·JaroWinkler(subj) + (1−w)·Indel(text)` (text only without SUBJ), same fields as Dedupe (`dedupe_records`), via `rapidfuzz.cdist`. Writes `annuaires/alignements/<left>__<right>.nw.csv` (same columns; `source` = `nw` anchor / `nw-contexte` (score = posterior) / `nw-residuel`; `--no-context` = plain NW), never applies the patch, and prints the estimated transitions and its agreement with the `.dedupe.csv`. ~12 s on 1807/1808. `display_alignment.py` lists both `*.dedupe.csv` and `*.nw.csv`.
   - **Review reasons** (`lib/alignment_review.py`, shared by the viewer, the export and `tools/audit_alignment_review.py`): the alignment itself is unchanged; after the fact, per segment (same similarity as the NW script), each link gets reasons — `déduite des voisines (p < 0,9)` (`nw-contexte` posterior < 0.9), `homonyme proche` (`nw`/`nw-residuel`/`dedupe` link with another entry of the segment within `margin` 0.05 of similarity) — and **unmatched candidates** (source/status `candidate`, reason `candidate non appariée`, never a link: two unmatched entries, mutual best in the segment, sim in [τ ; θr[ of `align_directories_nw.Params`, never a patch-declared uuid) are added. Ordinal uncertainty `LEVEL_LABELS` = `faible` (no reason) / `moyenne` (one) / `forte` (candidate, several reasons or posterior < 0.7) — not a probability, nothing learnt on a volume; keep the three labels on that single uncertainty axis (no "à relire" / "très incertaine"). Viewer: last column = explicit row status badge (`✓ appariée` / `relue` / `relue, incertaine`, `? non appariée · candidate à décider`, `✗ sans correspondance`) + score + uncertainty badge and reason (the `candidate non appariée` reason is not repeated under the candidate status), legend in a "ℹ️ Légende" popover next to the pagination; one "Rubriques" expander = paired section groups then lone sections, with entries / matched / rate per side and uuids; row accents (green border pair, amber background candidate, grey border alone); `CANDIDATE` kind in `lib/alignment_export.py`, not counted as matched; "incertaine" copy button. Sidebar from common to fine: alignment, Filtres (row status, Incertitude, section, search, score, manual), Affichage, Export, then a collapsed "Réglages fins de la relecture" expander (candidate threshold, homonym margin — read first via `st.sidebar.container()` placeholders because they feed the cached computation); no reason filter for now. Conventions: `docs/guide_relecture_alignement.md`. Why not a finer residual pass: on the labelled 1807/1808 inversion gold the 0.85 rule is ~93 % precise, the recoverable gain is ≤ 0.5 % of pairs and needs external knowledge, displacement (absolute or relative to section size) carries no signal, and unsupervised displacement priors failed (`docs/alignement_ordonne.md` § 6.1). For a new pair of directories, label a small gold and run the audit before trusting the thresholds.
   - `tools/export_alignment.py` — readable join of the two aligned volumes for data users (historians): takes any alignment CSV (`.dedupe`/`.nw`/final), reloads both volumes, applies the entry patch in memory (never rewritten; `--sans-patch`), writes `<input>.jointure.csv` (`--excel`: `;` + UTF-8 BOM; `--candidates` adds unmatched-candidate rows; `--ecart` = homonym margin). One row per pair / unmatched entry in the viewer's natural order; French columns `statut, score, methode, certitude, niveau_incertitude, motifs_relecture`, then per side `gauche_`/`droite_` + `volume, page, rubrique, texte, sujet, description, adresse, texte_balise, uuid` (span texts Markdown-normalized, several spans of a class joined by ` | `). `lib/alignment_export.py` holds the natural-order join (`natural_rows`, also used by the viewer's table) and the CSV export; the viewer's sidebar button exports the currently filtered/sorted rows in the same format.
   - **Section correspondence** (`lib/section_alignment.py`, shared by `align_directories.py`, `align_directories_nw.py` and `display_alignment.py`): a section = contiguous ENTRY run of one `Record.section`, identified by its TITLE uuid (`Record.section_uuid`; one title per section key in 1807/1808). Sections are aligned by Needleman-Wunsch on Jaro-Winkler of their key (threshold 0.8, `lib/sequence.py`), after the hand-edited, versioned patch `data/alignement/<left>__<right>.sections.csv` (`left_uuid, right_uuid, left_title, right_title, note`): pair rows are linked and their connected components form 1-1/1-N/N-M groups (removed from the automatic alignment; NW aligns a manual group's concatenated entries, free of order), a single-uuid row declares a section unmatched (never pooled into a NW gap). Lost uuids are re-anchored by unique `clean_title` of the recorded title (patch rewritten by the scripts, not by the viewer), else orphan. Dedupe compares `section` through `canonical_keys` (group → key of its first left section, idempotent), applied to the data and, on read, to the training JSON pairs (`canonical_training`), so no relabelling. `align_directories.py --raw-sections` keeps the original per-volume keys, writing `<left>__<right>.rubriques-brutes[.dedupe].csv`, so both variants can be compared on a gold (the viewer derives the pair from the file name up to its first dot). **Entries are only ever matched between paired sections** (so recall depends on the section patch; the inversion gold, drawn within segments, cannot see entries of unpaired sections — `tools/audit_alignment_review.py` lists them in its section 4, 42 entries of 1808 on 1807/1808): `restrict_to_corresponding(links, left, right, alignment)` drops any other link (Dedupe produces some: 16 on 1807/1808; also patch pairs, reported) in `align_directories.py` (raw and final outputs, also `--sans-dedupe`), the viewer ("Liens écartés" KPI + expander for patch pairs) and the export.

**Replayable human corrections (`lib/curation.py`; user guide with examples: `docs/guide_curation.md` — keep it in sync with the protocol):** one protocol for every hand-curated step. A curated step's output CSV is both machine output and the file edited by hand (Excel/OpenRefine, whole-document context); each row has a stable key, editable fields, `corrige` (`oui` = corrected or validated as is) and `empreinte` (hash of the machine's editable fields). Each run: (1) **capture** — if the output exists, its `corrige = oui` rows rewrite the versioned patch `data/curation/<document>.<step>.patch.csv` (git is the safety copy); (2) generate; (3) **apply** the patch (patch wins). It succeeds entirely or writes nothing: `CurationConflict` (**panic**) on an edited row without `corrige` (fingerprint mismatch), a correction that no longer applies (key gone, NER text changed upstream, parent title gone), or a machine line erased or moved in the lines file. `--force` takes the new machine output for those rows (also how to cancel a correction: clear `corrige`, rerun with `--force`); `--sans-capture` restarts from the versioned patch (always the versioned path, no override). Lines step: delete = class `SUPPRIMÉE` (`DELETED_CLASS`); a row added without key or duplicated gets `<base key>+n`, the patch keeps its position (`apres`); move = `SUPPRIMÉE` + keyless copy (machine lines keep OCR order). Line key `cle` = 12-hex sha1 of the frozen-normalized OCR text (`normalize_text`: NFC, nbsp, whitespace — never change it) + `~n` from the 2nd identical text; independent of page and block segmentation, unlike `uid`. Alignment patches (`data/alignement/`) follow the same rules (patch wins, orphans panic, `--force`) but are edited by hand from the viewer, not captured; their atomic writes go through `lib/curation.write_csv`. Data commits stay separate from code commits (prefix `données:`); scripts never commit.

**Shared code lives in `lib/`** (scripts at the repo root import it as `lib.…`, so run them from the root):
- `lib/curation.py` — the replayable-corrections protocol above (`Step`, `Curation`, `CurationConflict`, `line_keys`, `fingerprint`, `refuse_orphans`, `document_name`, atomic `write_csv`).
- `lib/chandra_document.py` — the pages → `data_blocks` → `lines` JSON shape, validated and iterated in one place (`iter_line_locations`), used by `annotate_lines_crf.py`, `export_lines_csv.py` and the CRF core. Change the schema there.
- `lib/stats.py` (page bootstrap, intervals, calibration, ROC AUC, review capture) and `lib/reporting.py` (Markdown helpers) are shared by both audits.
- `lib/alignment.py` — volume loading, Dedupe fields, entry similarity (`similarity_matrix`) and link CSV I/O for step 6; `lib/alignment_review.py` — review reasons, uncertainty level and unmatched candidates; `lib/alignment_patch.py` — the manual-correction patch of entries; `lib/alignment_export.py` — natural-order join and readable CSV export; `lib/section_alignment.py` — section correspondence, its patch, the entry segments (`segments`, paired groups only) and `restrict_to_corresponding`; `lib/sequence.py` — Needleman-Wunsch; `lib/pair_hmm.py` — pair-HMM of `align_directories_nw.py`.
- `lib/titles.py` — heading level and readable text of TITLE rows, shared by `build_entity_tree.py`, `lib/alignment.py` and `display_directory.py`.
- `lib/ner/` — NER: spans and their representations (`spans.py`), HTML rendering of spans shared by both viewers (`html.py`), typographic shapes (`shapes.py`), NER CSV reader and Label Studio text sets used for exclusions (`corpus.py`, `ls_texts`), gold metrics (`metrics.py`), review-priority reasons (`suspicion.py`), model loading/prediction (`gliner.py`).
- `lib/crf/` — CRF core. `features.py` defines named feature groups (`PRODUCTION_GROUPS` = exactly what the annotator uses, computed on Markdown-normalized text via `normalize_line` — emphasis markers, leading `#` and trailing spaces stripped, italic kept as the `italic` bucket feature; `LEGACY_GROUPS` reproduces the pre-v2 production set bit-for-bit for comparison (`production_v1` in the audit); `CANDIDATE_GROUPS` and `PLACEBO_GROUPS` are only evaluated by the audit). `model.py` wraps python-crfsuite training/marginals, `active_learning.py` holds `SourceLine`/`load_json_lines`/`ActiveCRF`; `annotate_lines_crf.py` keeps only the Rich UI, sessions and CLI.
- Changing production features changes annotator behaviour; to try a feature, add a candidate group and run the audit instead.

**CRF audit (`audit_crf_features.py`):** uses the hand-corrected `*.ocr.lines.annotated.csv` (column `classe`, `SUPPRIMÉE` rows excluded; original model labels read from the sibling `*.ocr.lines.annotated.json`) as silver ground truth. `lib/crf/silver.py` takes observations from the sibling `*.ocr.lines.json` (what the annotator saw) and attaches curated labels by the line key `cle` (both JSONs and the CSV must carry it; lines added by hand have no observation and are ignored) — curators also edited text (notably `#` heading markers), so computing features on the curated CSV text would leak labels. Curated labels differ from the original model predictions on only ~0.2 % of lines, so absolute scores are optimistic. `lib/crf/evaluation.py` runs page-contiguous within-document CV and leave-one-volume-out CV in parallel processes, with page-level (cluster) bootstrap; placebo feature groups give the noise floor used for verdicts.

**NER audit (`audit_ner.py`):** Ground truth is the hand-reviewed stratified, weighted gold `data/ner/gold.ls.json` (Label Studio; committed; `dev`/`test` split fixed — never tune on `test`). Hand-corrected rows of the `*.merged.ner.csv` files (`corrige = oui`) are only a partial review: silver, not ground truth. `audit_ner.py` only evaluates the systems it is given (`--model`, `--predictions`); on the dev split one `courant` entry weighs ~1.5 points, so also compare raw error counts. Annotations are compared on Markdown-normalized text (`normalize_markdown` + `project_spans`); join NER CSVs to merged CSVs on `uid`; exclude training data by normalized text, not uid. Scripts in `tools/` add the repo root to `sys.path` to import `lib`.

The line-level BIO classes (steps 2–4) and the span classes `SUBJ/DESC/ADDR` (step 5) are separate label spaces. If you rename a line class, update `build_entity_tree.py` too — unknown classes are treated as out-of-scope and only flagged in the report.

`tools/` holds the NER training and gold tools (`train_gliner.py`, `build_ner_training.py`, `sample_ner_gold.py`), the result viewers (`display_directory.py`, `display_alignment.py`), the alignment export (`export_alignment.py`), the review audit (`audit_alignment_review.py`) and the inversion gold sampler (`sample_alignment_gold.py`: NW-unmatched pairs crossing ≥ 1 ordered pair, best crossed partner per left entry, strata displacement × similarity, weight = stratum size / drawn; hand-labelled column `meme_entree` = `OUI` / `NON` / `INCERTAIN` (never "unsure"); never overwritten without `--force`). It exists because unsupervised estimates of a displacement-aware residual pass failed on 1807/1808: the identical-SUBJ sample misses moved entries (they mostly moved because their name changed spelling), and letting EM learn p(sim | different) diverges. Scripts that were no longer used (`main.py`, the LLM pre-annotator `autoclassify_labelstudio.py`) were deleted; the git tag `avant-menage` points to the last commit that has them (`git show avant-menage:<file>`).

`explorations/` holds exploratory notebooks (deps in the `explorations` dependency group: Jupyter, matplotlib; see `explorations/README.md`); they run from `explorations/` or the repo root and are committed with their outputs. `consolidation_adresses_1807_1808.ipynb` classifies the ADDR fields of aligned 1807/1808 pairs (équivalence / changement de numéro / déménagement / adresse complexe, plus sans numéro / adresse absente; street names normalized, fuzzy threshold ε) and exports `<jointure>.consolidee.csv`.

## Data

`annuaires/` (per-volume working folders), `*.pdf`, `*.gpkg` and `uv.lock` are git-ignored. Pipeline outputs live next to their inputs in `annuaires/<volume>/`. Human decisions live in versioned `data/` (`data/curation/` patches of steps 3 and 5, `data/alignement/`, `data/ner/`).

**Format changes: ask, don't default to backward compatibility.** Before a change that alters the shape of data files (JSON/CSV columns, keys, uuids, file names, patch formats), ask the user which way to go: (a) keep the code backward compatible with the old files, or (b) migrate the existing data once (a one-off script, dry run first, backup of the git-ignored `annuaires/` files it touches) and make the code accept **only** the new format (fail loudly on old files, no fallback branches). Default recommendation: (b) — compatibility branches pile up and make the code heavier, and git keeps every former version. After a migration, delete the one-off script and the obsolete files/options it made unnecessary, and remove "formerly…" / "older file" mentions from code, docs and this file.
